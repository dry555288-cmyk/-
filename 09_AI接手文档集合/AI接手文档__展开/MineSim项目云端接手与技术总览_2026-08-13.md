## **3.1 P0：先判断 C/D/E 是地图缺口还是 CollisionLookup 假阳性**

接手任务的第一原则是：先用标准 XG90G 物理 CarFootprint 测地图真值，不允许用 CollisionLookup 的离散几何来决定是否扩大 bitmap。

- 标准 XG90G：reference point=rear axle；front=+6.5m，rear=-2.5m，width=4.0m。

- 旧 C failure：step9，x≈2418.8165，y≈1393.1110，yaw≈-1.0070；lane5043，距 path tail≈2.711m。

- 旧 D failure：step64，x≈1533.5477，y≈3569.6566，yaw≈1.3241；lane6942，距 tail≈2.361m。

- 旧 E failure：step15，x≈1547.8949，y≈3571.7153，yaw≈-1.5313；lane6988，距 tail≈2.185m。

- runtime check_drivable 实际调用 CollisionLookup.collision_detection(rear_axle.x-X0, rear_axle.y-Y0, heading, bitmap)。bitmap 在 loader/runtime 中采用 np.flipud 对齐逻辑坐标。

## **3.5 CollisionLookup 根因 1：XG90G 前后悬语义反置 + 四边形角点错误**

低内存 sparse 诊断仅读取 C/D/E 局部窗口，避免整张 1.83GiB bitmap 加载导致 RC=137。诊断结果非常明确：标准物理 footprint=0 bad，但 CollisionLookup 仍命中黑像素，且 lookup longitudinal range≈\[-6.5,+2.6\]m，而正确物理范围应为\[-2.5,+6.5\]m。

| **原源码问题**                                          | **影响**                                                      |
|---------------------------------------------------------|---------------------------------------------------------------|
| MineTruckXG90G.collision_lrear=6.5；collision_lhead=2.5 | 把 rear/head 含义与真实 rear axle 几何反置。                  |
| p1.x = center - collision_lrear / 2 / c_size            | p0/p1 后边不共线，实际 polygon 变成梯形而非矩形。             |
| \_p\[0:4\] 后续直接旋转、描边、scanline 填充进 \_lookup | 没有任何后续补偿，因此错误直接进入 runtime collision lookup。 |

### **3.6 CollisionLookup 几何修复与回归**

- XG90G collision_lrear: 6.5 → 2.5。

- XG90G collision_lhead: 2.5 → 6.5。

## **5.5 地图修改纪律**

- P0 baseline、candidate v1、candidate v2 都视为 immutable；新 patch 必须另建目录和新 SHA。

- 严格 additive-only：ADDED 精确匹配预期像素集合；REMOVED=0；OTHER_CHANGED=0。

- 地图 patch 的依据必须是标准物理 XG90G footprint，不是 CollisionLookup 离散 occupancy。

- 如果扫描范围仍在边界有 bad（例如 B2 恒曲率 +12m/route-offset +25m），不得直接构建 patch；必须获取真实闭环轨迹。

- 每次 runtime 临时切图必须通过 symlink 原子切换，不要 cp -f 写 symlink 目标。

## **5.6 诊断优先级：先区分 blocker 类型，再修改**

|--------------------------------------|-----------------------------------------------------------------------|------------------------------------------|
| STANDARD footprint bad \> 0          | 是真实 map gap；先扫真实动态 corridor/trajectory，再 additive patch。 | 不要把所有 lookup sampled pixel 都涂白。 |

## **8.1 已确认的时间/索引关系**

- MineSimDynamicScenario.get_time_point(iteration) = origin + iteration×0.1s。

- get_tracked_objects_at_iteration(i) = \_detections_tracks_frames\[i\]。

- EnvironmentSimulation.get_planner_input() 读取当前 time_controller iteration。

- propagate() 使用当前 iteration 保存 history，然后 next_iteration，再 update ego/observations。

- 因此 shadow step N 是 iteration N 状态；从 step N-1 推到 step N 的 planner decision 使用 iteration N-1 objects。
