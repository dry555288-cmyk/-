# 3. 历史工程基座：按真实主线交接

## 3.1 MineSim原项目复现

**目标与输入。**以Dapai、Jiangtong官方成品场景/地图和Replay对象建立可信仿真基座，而不是以动画替代车辆闭环。历史IDM＋Replay复现完成，后续Planner改动以此为对照。\[H01；H03\]

**真实执行栈。**Scenario/Map → Planner → Trajectory → Controller → Kinematic Bicycle Model（KBM）→ Observation → Metrics/History → 下一帧。Planner输出未来轨迹，控制器再跟踪，车辆模型积分产生实际下一状态。Planner轨迹合法与Controller可跟踪不是同一验收项。近期教师采样属于规划模型续行，不覆盖这条完整车辆闭环。

**历史锚点。**IDM稳定基线commit为2521aa41a69a6e734c04c15a715e9530c8095ac3，tag为idm-replay-autodl-baseline。它是历史已记录版本，不是本次查询的当前HEAD。原始备份索引包括mcts_results与minesim_idm_baseline_backup；本次不检查其实时目录。\[H01；H03\]

**状态与恢复。**作为历史已完成基座保留，不因换对话重跑。只有将来核心Planner/Controller/车辆几何改动确实涉及回归时，按冻结配置恢复指定场景，不重做全部工程。具体未随本包携带的大型原始地图/视频从历史manifest定向取回。

## 3.2 Pure MCTS独立接入与单车

**实际工作。**把MCTS从IDM中分离，建立独立Planner、搜索、状态、转移和奖励模块，修复配置嵌套、奖励回传和动作转可执行轨迹。关键路径包括devkit/sim_engine/planning/planner/local_planner/mcts_planner.py及planner/mcts目录。源码名称用于定位，实际版本由当前对应manifest绑定，不以旧短commit替换。\[H01；H03\]

历史四动作是BRAKE、DECEL、KEEP、ACCEL，加速度依次−3、−1.5、0、+1 m/s²。历史单车正式参数记录过预算300、深度8、树步长0.5秒、探索系数1.4、折扣0.99；当前新教师使用B64/H8，不能混用。搜索后只执行首动作，再从新观测重规划。

**结果与界限。**Dapai、Jiangtong均有正式单车Safe Goal记录。Dapai对照体现多步冲突处理的价值；Jiangtong中IDM也成功且可能更快、更平顺。因此不能写MCTS在所有场景普遍优于IDM。历史50/100/200/300预算消融为预算自适应、价值引导提供动机，不直接证明某种神经加速有效。\[H03，第7、9、10节\]

五Planner包含MCTS、IDM、Frenet、Adapted Maneuver与Simple，部分分支的信息条件不同，例如使用replay future truth。该旧表只能作为统一仿真和评价协议下的异构能力比较，不能升级成完全公平排行榜。

## 3.3 双车冲突构建与J117

**目标。**验证两个受控车辆是否能通过联合规划形成时序协调，区分空间路径交叉与实际同时冲突。Dapai A-B-only存在B先A后的机制证据；external object1曾干扰目标交互，作为混杂因素记录。Jiangtong Traj26虽然相交，但到达时间差约9.496秒，被负筛选封存，不应通过修改StartTime或速度包装成天然冲突。\[H01；H03\]

J117是来自真实GeoJSON的构造benchmark。历史NO-MCTS对齐基线crossing gap约0.00070秒、净距0；Pure MCTS seed0 gap约1.561秒、swept minimum clearance约0.594米，5seed冲突消解与swept检查通过。这些数值只对应该历史构造场景，不是全矿安全保证。\[H03，第11节\]

**输入、输出与恢复。**输入为两条冻结路线、A/B初态及控制身份；输出包括真实A/B状态链、冲突/净距/通行时序、种子结果。A/B受控车不能又作为external actor；B真值与可视化不能由A history推断。J117和历史失败状态原样保留，除非涉及真实代码影响，不重新调seed、reward来重复验收。

# 4. 旧神经接入、K13与旧教师数据

## 4.1 旧Value V3已经做过什么

旧Value V3已真实参与根节点评分、排序和门控；其目标是根内成对排序，不因为沿用12→64→64→16架构就继续称作绝对ROOT_CENTERED_Q回归。历史标签/归一化/动作顺序必须与各自源码版本一起绑定。\[H01，第1、4章\]

旧K13局部16→13动作减少机制成立，但匹配运行证据**没有建立稳定、可复现的端到端加速**。该分支冻结关闭；不能通过换seed、补缺失试次或调阈值挽救原结论。某处搜索动作减少不等于总耗时下降，网络推理、状态访问、实际展开、总wall time需要分别计数。

旧接入不等于已实现PUCT先验、叶节点价值回传或安全节点删除。近期新26维模型没有获准替换旧Value V3，更不能把两代checkpoint、特征或门控策略混合部署。统计保证型动作排除的风险限额、假设和误差预算独立HOLD，不将其前提强加为全部开发的停工原因。\[H01\]

## 4.2 为什么没有只靠增加训练轮次

历史教师诊断发现重复状态、根动作访问支持不足、预算增加但个别低Q动作仍只访问一次、均衡根访问降低波动而预算漂移仍在等问题。864-cell诊断改善的是采样重复性，不是“准确率提高同等百分比”，也不证明所有2356条旧数据失效。来源绑定、重复关系、覆盖增补和预测时域的诊断均应保留。\[H01\]
