# MineSim 双车输入与监督信号诊断

**结论：只读诊断已完成；当前512条数据保持冻结，不再采集。本步没有拟合、模型前向、MCTS或远程执行。**

## 1. 本步具体核对范围

读取最新双车正则模型结果包中的DATASET32、COMBINED32、特征函数、协议和结果，以及已上传采集器小试中的双停稳状态编解码源码、两个原绑定上下文和对应运行解析上下文，共10份定向来源。逐项核对大小、SHA与各自父清单，不重新累计旧的全量核验次数。

32个完整状态重新计算feature26，全部与实际训练输入逐项一致；状态SHA、特征SHA、任务/来源组和上下文SHA吻合。512条回报及两个4次重复分块的均值重算与保存值一致。每个来源组4个状态，32种特征字节均不同，没有发现“完全相同输入却被分配矛盾目标”的字节级别别名。这个检查不能证明整个物理模型正确，也不证明输入已经足够学习。

## 2. 输入维度多，但信息存在重复

26列中6列在当前32状态里恒定：两车的目标速度、到达标记和“无上一动作”标记。每车的路线进度比例与剩余比例互补，两个目标边界相差固定0.5m；命令加速度与上一动作编码对应。制动余量虽然是位置/速度的确定性变换，也可能具有有用的物理表达作用，不能因为冗余就认定应全部删除。

中心化矩阵奇异值显示，在绝对容差1e-6下描述性秩为12；1e-8附近的小奇异值主要提示浮点舍入和近线性相关。本报告不使用这个容差选择特征，不把“秩12”当作独立样本数，也不据此决定网络大小。

## 3. 新状态扩大位置覆盖，但多数状态的动作差异很小

|子集|状态数|经验回报差绝对值≤2|经验回报差绝对值>10|
|---|---:|---:|---:|
|旧16状态|16|6|9|
|新增16状态|16|14|1|
|合计|32|20|10|

“2”和“10”仅是便于阅读的奖励单位分箱，不是安全阈值、删数据规则或新增标签。新增状态是按位置/速度覆盖选的，而不是按尚未知晓的回报挑选。因此补充覆盖不等于补充了同等数量的强动作对比。

进一步按原上下文中已绑定的C11参考点（A路线位置227.77075274944568m，B路线位置266.5474890454852m）描述：两车都尚未经过各自参考点的状态为13个；其余19个状态的经验回报差介于−1.272和+2.025。11个出现CAP观测的状态全部在前一个子集中。参考点不是重新认证的冲突区边界；经过参考点不等于全车通过冲突区域。

**推断边界：**这些分布有助于解释为什么整体误差较低的模型可以近似常数，但不能唯一证明模型退化的因果原因。32个状态仍来自同一路线，未转换成盲测。

## 4. 当前难点集中在窗口内完成与未完成混合的状态

11个状态的16条记录中至少有一条CAP；其余21个状态全部在窗口内停稳。相对于原定“训练组均值常数基线”，这11个状态占约91.66%的绝对误差、99.55%的平方误差。这里按运行结果事后分组，只用于诊断，**不能把CAP/停稳结果作为网络预测时的输入，也不能只留下困难状态重新评价。**

8个状态的两组4次重复所估计的回报差相差超过10个奖励单位。最大者contrast_04：前半为+10.716，后半为+61.250，差50.534；它的方向可以重复成立，但差值大小仍不稳定。

在contrast_04中，动作0,3是8/8停稳；动作3,0是5/8停稳、3/8CAP。3,0停稳记录的平均回报约49.834，CAP记录平均约−18.817。这说明“同一动作的回报波动”不只是小数值扰动，还包含不同的任务完成情况。它不能证明所有监督失效。

所有45条CAP的64秒窗口回报都完整可见，完整任务尾段仍未知。保留全部原始记录，不把CAP当缺失数据、不改为碰撞、不补零。

每个状态另附样本标准差和 sqrt(sd03²/8+sd30²/8) 描述量。后者需要独立重复假设，是小样本代入估计，不是置信保证、误差下界或剪枝许可；本报告不使用它更改标签。

## 5. 一个必须纠正的字段含义

从dual_stop_adapter_v1.py的step_with_diagnostics可见：函数对一次0.5秒转换中的0.1秒采样几何求最小值，把它写入转换后的minimum_internal_clearance_m。所分析32个根均非初始step0，因此根状态中的这个字段是**上一段转换的采样最小净距**，不是必然等于根时刻瞬时净距，也不是未来动作执行后的净距。

此前“输入没有显式使用净距”的观察仍成立，但不能不加说明地把该字段当成当前瞬时几何。未来新增输入必须明确时点和来源，禁止使用所预测动作之后的最小净距。

## 6. 比单独加入净距更值得检查的是双车方向关系

下面只从当前状态和原绑定参考点计算d/v，不搜索、不调用运动模型。仅在尚未经过参考点且速度为正时定义；其他情况为不适用，而不是伪造无限时间或零时间。

|状态|上一转换采样最小净距m|A当前速度到参考点时间s|B当前速度到参考点时间s|观测回报差03−30|
|---|---:|---:|---:|---:|
|contrast_00|53.518|4.578|3.458|+61.055|
|newroot_02|50.518|3.486|4.417|−37.745|
|coverage_policy_05__step0011|68.163|4.263|4.447|+21.351|

前两个状态上一动作均为双车制动，净距数值接近，动作平均收益方向却相反。当前速度参考到达关系能够表达它们的区别，因此值得将方向关系明确提供给模型，而不是只堆叠每辆车的剩余路程。

第三行是保留的反例：A按当前速度估算会略早到达，但观测回报差仍偏向0,3。因此，**d/v不是已经验证的控制规则，更不是TTC或真实碰撞预测。**它忽略加速度、车身几何、后续交互和MCTS随机性。两个不同车辆的route_s不能直接相减后当作两车欧氏距离。

同一路线中，参考距离可由原路线位置和固定上下文导出。这类新输入改善的是表达方式，不应声称提供了原来绝对不存在的新信息或必然解决问题。

## 7. 本步收口与下一步建议

本步只读诊断已完成，不需要用户再运行云端检测。下一步建议固定“显式双车交互特征”对照设计：每车到各自参考点的有符号距离、是否已过参考点、两车当前位置/速度组合下的参考到达时间差及有效性标志。原26维是否保留、缩放和编码必须在新拟合前明确，不能用外层留出结果不断调整。

继续保留32状态/512条回报、全部CAP、8来源分组、Y64目标和原定主要指标。可以补充按参考点位置分组的开发描述，但不能据此换主指标、删简单状态或排除负结果。现在不新增采集、不训练、不开始剪枝、不转回单车。

NEXT_FEATURE_PROPOSAL.json仅是提案，不是训练或部署授权。当前仍没有证明神经辅助搜索提速或安全动作排除。
