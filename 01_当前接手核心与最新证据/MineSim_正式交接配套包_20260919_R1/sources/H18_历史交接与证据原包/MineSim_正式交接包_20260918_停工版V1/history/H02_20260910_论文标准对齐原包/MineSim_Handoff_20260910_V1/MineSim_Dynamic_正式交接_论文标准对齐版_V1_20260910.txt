一分钟理解本项目的变化

最初问题是“网络离线训练看起来尚可，为什么接入MCTS及剪枝后收益差”。后续没有直接增加训练轮数，而是沿证据逐层追查：先发现重复状态和低支持Q标签，再发现根访问分配失衡；均衡访问降低了数值波动，但完整排序仍不稳定。独立种子确认提取出可学习的部分关系，然而新状态上的泛化仍可能失败。来源拆分又把局部异常定位到两个相近C06状态，进一步证实4秒搜索截断遗漏的后段回报足以翻转排序。[E06；E11—E19]

随后建立了完整叶状态恢复、随机数恢复和折扣回报拼接；用明确续接策略获得到配置路线终点的执行回报；再回到原始根状态，强制执行一个动作后由冻结MCTS接管。完整回报虽然不再缺失这批样本的尾段，但不同动作很接近，均值第一名依然随批次变化。因此又区分了“经验比较”“统计保证”和“任务评价目标”：复合奖励不等于两车完成时间，统计置信参数也不等于交通安全限额。[E20—E28]

最后回查论文，发现论文并未统一要求先给出“最多慢多少秒”。当前恢复为两条清楚的路径：开发评价继续对齐交通安全、完成率、通行时间和搜索开销；有保证的动作删除独立保留HOLD。 这不是降低安全标准，而是不再把某一新增理论分支的前提强加到所有开发研究上。[E29]

2. 按真实主线恢复工程成果

2.1 MineSim复现：先建立可信闭环基座

阶段目标是复现原MineSim，而不是另写一个简化动画。Dapai、Jiangtong上的IDM＋Replay历史闭环完成，稳定IDM基线记录为commit 2521aa41a69a6e734c04c15a715e9530c8095ac3、tag idm-replay-autodl-baseline。输入为官方场景、地图及历史对象，输出包含真实逐帧轨迹、碰撞/边界/目标指标和可视化。它是后续Planner修改的回归基座，不应为重新接手而重跑。[E01；E03]

真正的执行栈是：Scenario/Map → Planner → Trajectory → Controller → Kinematic Bicycle Model → Observation → Metrics/History → 下一帧。Planner输出未来轨迹，不直接修改下一帧车辆位置。轨迹可生成，不等于控制器能跟踪；控制器异常也不能自动判为搜索策略失败。近期单根搜索和规划模型续行没有覆盖这条完整执行栈。[E03，第3节；S01，第22节]

2.2 Pure MCTS与单车：已经接入真实在线闭环

Pure MCTS在既有路线和轨迹接口内替代反应式纵向动作选择，没有重写所有车辆动力学。历史配置为预算300、深度8、树步长0.5秒、探索系数1.4、折扣0.99；四动作加速度见第3章。每帧搜索后只执行第一步，再根据新观测重规划。[E01，第7节；E03，第4节]

Dapai正式记录中MCTS达到Safe Goal而IDM发生冲突；Jiangtong两者均到达，IDM还可能更快、更平顺。五Planner历史比较还包含Frenet、Adapted Maneuver和Simple，但信息条件并不完全一致，部分分支使用replay future truth。因此准确称为“统一仿真与评价协议下的异构规划能力比较”，不是严格公平的五算法普遍排名。[E01，第9节]

50/100/200/300预算消融显示Dapai更敏感，Jiangtong较早饱和。这为后续value guidance、预算调整及搜索复用提供研究动机，但并未证明某个神经方法必然更快。预算300是历史单车配置，不能与近期教师根预算64或执行策略B64混用。

3. 统一符号、真实搜索与奖励实现

3.1 四种“状态／回报”不要混用

s表示规划模型完整状态，包含车辆路线进度、速度、加速度、航向、目标标志、时刻及对象/几何信息；x = ϕ(s) ∈ ℝ¹²只是网络输入。两个x完全相同，不自动证明两个完整状态、时间、上下文和随机过程相同。完整状态恢复必须保留原始provenance。[E07—E10；E20]

联合动作写作a = (a_(A), a_(B))。本项目canonical index及加速度枚举为：

i(a) = 4a_(A) + a_(B),   (a_(A), a_(B)) ∈ {0, 1, 2, 3}².

  编号   动作            加速度（m/s²）
  ------ ------------- ----------------
  0      BRAKE／制动               −3.0
  1      DECEL／减速               −1.5
  2      KEEP／保持                   0
  3      ACCEL／加速               +1.0

近期单根/续行使用树时间步长Δt = 0.5秒；历史运行记录root_step的仿真采集间隔可为0.1秒。不能用“相邻10个root_step”推成5秒。B表示整次树搜索迭代预算；H表示树深；T表示策略执行评价的最大步数；n表示外层重复执行样本数。[E15；E20—E24]

3.2 UCT、均值Q与最终根动作

依据Kocsis与Szepesvári的UCT框架，搜索包含selection、expansion、rollout和backup。项目冻结实现的已访问子节点选择形式是：[P01；E30]

$$\operatorname{UCT}(s,a)=\widehat Q(s,a)+c\sqrt{\frac{\log(N(s)+1)}{N(s,a)}}.\tag{F02}$$

未访问动作先扩展；具体未试动作顺序和随机扩展由源码决定。项目c = 1.4、γ = 0.99是其配置，不是所有论文共同常数。回传与节点估值为：

$$G_j=\sum_{k=0}^{L_j-1}\gamma^kr_{j,k},\qquad\widehat Q(s,a)=\frac{S_Q(s,a)}{N(s,a)}.\tag{F03}$$

其中S_(Q)(s, a)表示源码中的value_sum累计回报字段。实际回传递推为r + γG_(next)。早期核查未发现“忘除访问数”“终止惩罚重复扣除”的所述路径错误。最终Pure MCTS根动作按访问次数优先，再按Q，再按较小动作ID打破并列；不能把训练Q最高动作与控制器最后选择动作混成一个监督对象。[E06；E30]

$$a_{\mathrm{exec}}=\underset{a}{\operatorname{lexargmax}}\bigl(N(s,a),\widehat Q(s,a),-i(a)\bigr).\tag{F04}$$

F04是对当前源码选择语义的数学表示，不是对所有UCT实现的定义。默认均匀随机rollout只在当前可用动作中采样，已到目标车辆的动作域缩小；随机种子控制伪随机流，同一整数seed并不保证不同算法/动作消耗相同随机数或形成相同轨迹。

3.3 两个C06诊断状态的奖励：来源和单位

本节是近期C06冻结配置的公式展开，不是全项目所有场景的统一参数。对尚未完成的车辆v，单车奖励包括进度、目标速度偏差、TTC/外部净距和加速度变化；Fleet层除以原控制车辆数2，再加内部净距及一次硬安全惩罚。某车已到目标后不再累加它的普通单车项，分母仍为2，而非改成当前未完成车辆数。[E27；E30]

令clip₀₁(z) = max (0, min (1, z))，v_(ref) = 10.5 m/s，则本配置的主要分项为：

$$r_{\mathrm{prog}}=\frac12\sum_{v\in\mathcal V_{\mathrm{active}}}\frac{\max(0,\Delta s_v)}{v_{\mathrm{ref}}\Delta t},\qquad
r_{\mathrm{speed}}=-\frac12\sum_v0.3\frac{\operatorname{abs}(v'_v-v_{\mathrm{ref}})}{v_{\mathrm{ref}}}.\tag{F05}$$

$$r_{\mathrm{TTC}}=-\frac12\sum_v2\max\left(0,\frac{3-\mathrm{TTC}_v}{3}\right),\qquad
r_{\mathrm{comfort}}=-\frac12\sum_v0.3\frac{\operatorname{abs}(a'_v-a_v)}{10\Delta t}.\tag{F06}$$

$$r_{\mathrm{int}}=-0.5\operatorname{clip}_{01}\left(\frac{3-d_{AB}}{3}\right)^2,
\qquad r_{\mathrm{hard}}=-100\,\mathbf1_{\mathrm{hard}}.\tag{F07}$$

外部净距项形式为负权重乘clip₀₁((3 − d_(ext))/3)²后按车辆平均；该局部配置权重为0。原单车goal_bonus为30，经Fleet两车平均后，每辆车首次到达贡献15。全部分项及到达奖励满足：

r = r_(prog) + r_(speed) + r_(TTC) + r_(ext) + r_(comfort) + r_(goal) + r_(int) + r_(hard),  G = ∑_(c)G_(c).

这里3米是净距软惩罚尺度，不是已经批准的3米硬安全约束。近期全部384条根动作策略轨迹中某些风险分项恰好为0，也不能从一般评价契约中删除风险指标。hard_safety_violation必须使用冻结模型的实际字段；搜索树内想象中的硬事件与真正执行动作后的硬事件，分开记账。

3.4 三类Q与一种分数

  --------------------------------------------------------------------------------------------------------------
  对象                    实际含义                                         不可替代的对象
  ----------------------- ------------------------------------------------ -------------------------------------
  Q̂_(H, B)                某次有限树搜索、该预算和自适应访问下的动作均值   完整任务真值、所有动作均充分采样

  Q_(T)^(π)               强制首步后由明确策略π执行至终止/上限的期望回报   最优Q^(opt)，或原树内Q

  Q_(time) = −𝔼[C₆₄]      以秒为单位的辅助成本负值                         原搜索的折扣复合回报

  --------------------------------------------------------------------------------------------------------------

为避免混淆，公式中的opt表示通常写作星号的最优值，abs表示绝对值，norm表示范数，card表示集合元素数。该区分是本次交接的核心。后续每次训练、比较和剪枝，都必须先声明目标是哪一种。

4. Value V2、Value V3与K13：方法及冻结结论

4.1 模型架构相同，不代表训练目标相同

历史Value V2为ROOT_CENTERED_Q路线；其摘要记录模型12→64→64→16、normalization/feature mapping等静态检查完成，C03 forward和metrics当时尚未执行。V3设计改为直接优化动作相对排序，保留两层64单元ReLU隐藏层和16输出。近期masked诊断网络又在相同架构上改变了监督mask与权重。因此必须分别记录“旧V2”“旧V3”“新诊断模型”，不得统称为同一个已重训模型。[E02；E05；E12]

12维输入按历史定义为A/B速度、A/B加速度、两车到冲突参照点的剩余距离、绝对速度差、绝对航向差、航向差除以π、两车同时在approach区域标志、同时在intersection区域标志及α₃。特征顺序必须按保存helper绑定；名称相同也要核对单位、计算时刻和区域几何。[E02；E04；E30]

训练折独立归一化的一般形式为：

$$z_j=\frac{x_j-\mu_{j,\mathrm{train}}}{\widetilde\sigma_{j,\mathrm{train}}},\qquad
f_\theta(x)=W_3\operatorname{ReLU}\!\left(W_2\operatorname{ReLU}(W_1z+b_1)+b_2\right)+b_3.\tag{F09}$$

当前新诊断训练的σ < 10⁻⁸列使用scale=1；该细节来自诊断协议，不反向推定所有历史V2/V3训练都用完全相同代码。已有归一化与在线输入一致性检查支持指定文件版本，不代替任意新模型的版本绑定。[E12]

4.2 旧V3：Q差加权的成对logistic损失

RankNet原文将分数差通过sigmoid映射为成对偏好概率，并最小化交叉熵。对于确定方向y_(ij) ∈ {−1, +1}，可写为softplus [−y_(ij)(f_(i) − f_(j))]。这里的概率是模型成对偏好参数，不是驾驶安全概率。[P02，式1—3]

历史V3设计源码给出以下项目适配：对每个root，d_(ij) = q_(i) − q_(j)，跳过d_(ij) = 0，令：

$$y_{ij}=\operatorname{sign}(d_{ij}),\qquad
w_{ij}=\frac{\operatorname{abs}(d_{ij})}{\max(q_{\max}-q_{\min},10^{-12})}.\tag{F10}$$

$$\ell_s^{\mathrm{V3}}=
\frac{\sum_{i<j}w_{ij}\operatorname{softplus}[-y_{ij}(f_i-f_j)]}{\sum_{i<j}w_{ij}}.
\tag{F11}$$

再按场景等权、场景内root等权聚合。历史设计为Adam、学习率0.001、固定600轮，无early stopping。阶段审计指出完整逐轮训练/验证曲线未保存，故“训练执行完成”可以确认，“旧网络充分收敛”仍是HOLD。[E05—E06]

F10—F11的权重不是RankNet原论文统一要求，而是项目设计；不读取根动作访问数或回报方差。一次低支持估计若形成很大的Q差，就可能成为强排序监督。标签归一化去掉了跨root的整体Q尺度，却没有自动消除标签噪声。

历史离线评价使用归一化regret等指标：

$$\widehat a_s=\arg\max_af_\theta(x_s)_a,\qquad
\operatorname{NR}(s)=\frac{q_{\max}(s)-q(s,\widehat a_s)}{\max(q_{\max}(s)-q_{\min}(s),10^{-12})}.\tag{F12}$$

其意义是“相对该教师Q的损失”，不是相对真实最优驾驶策略的损失。历史C01中位归一化regret约0.10584，优于即时奖励基线0.29520，说明指定离线评价确有排序信号；不能由此证明教师稳定、闭环更好或剪枝安全。[E06]

4.3 网络如何接入MCTS：根排序，不是PUCT或叶值

旧Value V3 online scorer先从根状态生成12维特征、加载冻结归一化和checkpoint，再输出16个分数。按分数降序及较小canonical ID打破并列，得到根动作顺序。原树内UCT、rollout和backup保持。该分支不是AlphaZero式策略先验PUCT，也没有把网络分数接入叶节点价值回传。[E04，第3—5节]

置信度门控使用：

m(x) = f₍₁₎(x) − f₍₂₎(x).

这是top1与top2分数差，不是Top13/14边界差，也不是经过校准的正确率或置信区间。冻结三段式机制为：

$$\begin{aligned}
m<\tau_o &\Rightarrow M_0,\\
\tau_o\le m<\tau_p &\Rightarrow M_1,\\
m\ge\tau_p &\Rightarrow M_2.
\end{aligned}\tag{F14}$$

M_0对应PURE_FULL（原顺序、全动作），M_1对应NEURAL_ORDER_FULL（神经排序、全动作），M_2对应NEURAL_TOPK_PRUNED（根Top-K剪枝）。

冻结参数τ_(o) = 0.06767839193344116、K = 13、τ_(p) = 1.2940582036972046。异常空候选执行full recovery；剪枝只作用于depth=0的untried_actions。每个root在判断门控前都支付一次forward。技术实现、参数选择与工程结果不能混为一个PASS。[E04]

4.4 K13如何选出来，为什么不能当成安全保证

开发数据为151个unique root；三个runtime seed生成453条raw记录，但root和target完全重复，不能当453个独立状态。三个模型各对151个root评分，共453个model–root组合。K8扫描425个阈值诱导子集仍无合格解；预先固定的K-ladder 9→15选择最小可行K，K13首先满足pooled及各模型seed的Top-K target retention≥99%。[E04，第7—10节]

$$\operatorname{Retention}_{K,\tau}
=\frac{\sum_{s:m_s\ge\tau}\mathbf1\{a_s^{\mathrm{teacher}}\in\operatorname{TopK}(f_s)\}}
{\operatorname{card}\{s:m_s\ge\tau\}}.\tag{F15}$$

高置信支持为178/453，观察保留率100%，覆盖39.2936%；触发时删3/16=18.75%，静态平均候选减少约7.3675%。这些是开发集经验统计，不是“无损剪枝概率100%”。三个模型共享状态，不能把model–root对数当作完全独立校准样本。K13、99%和两个τ都是项目预先固定规则/选择结果，不是交通风险论文或RankNet原文给出的常数。

5.2 低预算教师为什么容易把一次坏估计固定下来

在最初可核查的2084个root、33344个动作标签中，2811个Q < −90条目全部只有一次访问。“−90”只是审计统计分箱，未成为自动删标签阈值。C11 100m的1562个此类标签也都是单访问，并且根动作第一步硬安全标志为False；源码奖励下界分析表明极低回报需要来自更后的硬惩罚，而非普通效率/舒适性项。[E06]

在B = 64, c = 1.4且动作仅访问一次时，探索补偿量级约为：

$$1.4\sqrt{\log(64+1)}\approx2.86.\tag{F17}$$

若一次随机未来使动作从约−3估到−98，这个探索项很难令其再次被检查。F17不是对每次事件的完整因果归因，而是源码支持的访问锁定机制。旧排序损失又会根据较大的Q差提高成对权重，形成“低支持坏估计→大分差→强监督”的风险链。[E05—E06]

6. 相对排序候选、36-root Pilot与来源修复

6.1 从完整Q真值转为“可靠关系／未知关系”

9-state结果提出的候选规范区分RELIABLE_ORDER、TIE_UNCERTAIN、CONFLICT_UNCERTAIN。其基本量是：

D_(z)^((B))(s; i, j) = Q̂_(B, z)(s, i) − Q̂_(B, z)(s, j).

结合动作范围归一化差距、种子方向一致、跨预算方向及种子分半方向检查。初版9-root候选使用至少15/16方向一致等规则，得到1080对中810可靠候选、199近似并列/不确定、71冲突不确定。它只是开发候选，不是置信保证；近似并列标记不证明真实等价。[E06]

2356条原数据多数只有单次B64搜索，没有足够多seed/多budget证据，不能仅凭静态改文件就生成上述可靠mask。因此进入36-root小样本新教师Pilot，而不是直接重采全部2356条或重训网络。

6.2 36条状态选择与原始记录错误的修复

36-root按C04/C06/C11各12条、6个episode各6条设计，覆盖早、中、晚及重复区代表，不按Q好坏选取。首轮取得26条，另外10条历史frozen记录定向恢复。此后发现两条step0误绑定：C04_FROZEN_EP0拿了seed5，C06_FROZEN_EP0拿了seed1。[E07—E08]

最终发现不是“只错provenance字段”。 两条记录的完整根状态及即时奖励相同，但16个Q和访问数来自不同搜索。正确修复是在新namespace取回真正seed0的原始记录，保留其余34条原字节；不是给错误Q换一个来源标签。原NPZ和原2356日志一致，错误发生在后来的Pilot记录绑定环节，不应归咎于全体原训练数据。

精确上下文还经历12/15来源匹配，缺3项dynamic_v2v/approach/omega_int freeze；原采集器只扫py/json漏掉ZIP，定向检查历史8个候选归档后找到3/3完整SHA。C11 100m manifest保留旧80m引用，但原始采集provenance指100m；两份冻结源都保留，实际重建按正确raw record而非旧指针初始化。[E08—E09]

36-root最终单步576次、12456项比较通过，最大误差约8.88 × 10⁻¹⁶；72次技术搜索日志开关的Q、访问数、最终动作、随机数状态一致。这证明重建和日志链，不证明教师质量。[E10]

6.4 偏好关系图不能补造未知边

把确认i ≻ j记作有向边；可检查循环与传递可达性。当前诊断图没有循环，只说明已确认关系内部自洽，不证明所有动作可比。定义尚不能排除的动作集合：

𝒞(s) = {a : ∄b，使当前确认关系中 b ≻ a}.

对于假设Top13删除集D₁₃，项目静态指标为：

$$\operatorname{UnsupportedDrop}(s)=\frac{\operatorname{card}(D_{13}(s)\cap\mathcal C(s))}{3}.\tag{F21}$$

F20—F21是项目的经验关系审查，不是最佳臂论文给出的安全删除保证。还需检查每个拟删除动作是否有一个保留下来的优势关系见证。未知边不补成并列；传递闭包也只依赖已有经验边，不能提高其统计认证级别。[E14；P09]

7. 新诊断网络：可学习性、泛化与覆盖对照

7.1 新mask损失：明确忽略未知关系

新诊断模型不加载旧Value V3权重，输出仍是16个排序分数。确定方向y_(sij) ∈ {−1, 1}、mask m_(sij) ∈ {0, 1}，对有监督的状态定义：

$$\ell_s^{\mathrm{mask}}=
\frac{\sum_{i<j}m_{sij}\operatorname{softplus}[-y_{sij}(f_i-f_j)]}{\sum_{i<j}m_{sij}},
\qquad \mathcal L=\operatorname{mean}_{\mathrm{scene}}\operatorname{mean}_{s\mid\mathrm{scene}}\ell_s^{\mathrm{mask}}.\tag{F22}$$

动作对在状态内等权，输入组在场景内等权，场景等权；不再按原Q分差放大权重。m = 0完全不进入loss，不能将y = 0作为“并列真值”训练。F22继承RankNet的成对logistic结构，mask和分层权重来自项目协议。[P02；E12]

主要排序指标为状态内已确认动作对的正确比例，再按约定状态/场景聚合：

$$A_s=\frac{\sum_{i<j}m_{sij}\mathbf1\{y_{sij}(f_i-f_j)>0\}}{\sum_{i<j}m_{sij}},\qquad
\operatorname{Coverage}_s=\frac{\sum_{i<j}m_{sij}}{120}.\tag{F23}$$

必须同时报告F23的两项：在少量已知边上100%，不代表全部120对关系都正确。原分数精确并列由实现记录，不能用canonical tie-break冒充有数据支持的优劣。

7.4 新24状态：按覆盖选择，不按Q或网络表现挑点

借鉴core-set最远点覆盖思想，项目在约束候选集内迭代选择与旧33组及已选新状态最远的点：[P03，式5、Algorithm 1；E15]

$$x_{t+1}=\arg\max_{x\in\mathcal A_t}\min_{y\in L\cup S_t}d(x,y),\qquad
d(x,y)=\sqrt{\frac1d\sum_{j=1}^{d}\left(\frac{x_j-y_j}{\sigma_j}\right)^2}.\tag{F24}$$

实际覆盖距离使用七个与状态几何/运动相关的维度：两车速度、两车到参照点剩余距离、航向差、approach AND和intersection AND；归一化尺度按旧数据冻结。六个episode各4个，排除旧33组、指定旧诊断点及近重复/相邻点。24条、距离0.05、相邻10个root_step等是项目设置；约束和配额改变了原无约束问题，不能直接继承原算法2近似保证。

选点不读Q、奖励、访问数或网络分数。24组仍来自旧六个episode，不是新的独立最终测试集。包含20个运动中区域内状态、2个低速非零状态、2个运动中尚未进入区域状态。单步384次、8304项比较通过后，才进入教师采样。[E15—E16]

8. 时域问题：同轨迹后段回报足以翻转排序

8.1 先发现最后一层集中出现风险

两个定向状态为 NEW24__C06__C06_FROZEN_EP0__step76 和 NEW24__C06__C06_SEED1_EP1__step73。其H8/B1024已有16个seed记录中，step76的1217条含硬安全事件迭代，有1192条首次在第8步；step73仅3条，也都在第8步。H8×0.5秒=4秒，因此有明确理由检查时间窗口边界，而不是继续增加网络训练轮数。[E18]

诊断保持预算1024、根动作均衡、状态/奖励/折扣不变，复用H8的32组，新增H12/H16共64组；技术种子和科学种子分开。H12、H16是预先固定的项目敏感性设置，不是更深必然更正确的命题。

8.2 直接比较不同深度：标签方向大量变化

  包含硬事件的迭代数／每格16384条     H8／4秒   H12／6秒   H16／8秒
  --------------------------------- --------- ---------- ----------
  step76                                 1217       7602       8483
  step73                                    3       3264       5563

这些是自适应搜索迭代，不是独立驾驶碰撞概率。step73原84个确认动作对，在H12有52对全部16seed反向、32对方向混合；H16有40对全部反向、44对混合，没有一对在两种新深度中保持原方向的16/16一致。两状态共同52对在H8全反，H12均值仍相反3对，H16又增为9对。不能因H12“更相似”便事后选它作真值。[E19]

8.3 固定轨迹再分段：避免把所有变化归因于随机路径

改变树深也会改变自适应选路。进一步用同一批H16已采轨迹，只改变计入回报的前缀长度：

$$G_{16}(\tau)=G_8(\tau)+\gamma^8G^{\mathrm{local}}_{8:16}(\tau),\qquad
G_h(\tau)=\sum_{k=0}^{\min(h,\tau_{\mathrm{term}})-1}\gamma^kr_k.\tag{F26}$$

对固定H16轨迹，两状态共同52对的均值方向相反数，读取前8步为52、前12步为1、全部16步为9。注意直接H12搜索的3对与固定H16轨迹前12步的1对是两种不同审计，不能为了统一表格任意取一个。[E19；E19b]

step73同一批H16轨迹中，Q(0, 0) − Q(2, 3)前4秒约−1.596，后4秒带来的差值增量约+27.772，完整8秒变为+26.176；前缀与完整各自16/16支持相反方向。这说明在这些记录中，未计入的后段回报本身足以翻转排序。它不证明(0,0)安全最优，不证明全部2356条错误，也不等同于把原H8搜索原封不动继续运行。[E19]

8.4 为什么这不是简单的“代码算错了”

若教师目标明确就是未来4秒回报，H8标签可以合法；若希望它反映长期通行收益和剪枝安全，就需要检验截断后部分，不能把真实终止与人工窗口用完等同。原UCT Figure 1区分terminal返回0与leaf调用Evaluate。Pardo等进一步区分真正有限时域任务与采样截断。[P01；P08]

候选完整形式为：

$$Y=\sum_{k=0}^{L-1}\gamma^kr_k+
\mathbf1_{\{\mathrm{not\ terminal}\}}\gamma^L\widehat V_{\mathrm{tail}}(s_L).\tag{F27}$$

F27当时只是待实现契约，不是已训练的尾值网络。现有排序分数不能直接填入第二项，因为：

ℒ(f + c1, y) = ℒ(f, y).

F28只表示共同加性偏移不变，不表示任意缩放也不改变loss。排序监督无法单独识别绝对回报的零点；给16个分数共同加100也不影响排序，却会完全改变价值回传。应先明确续接策略、时间范围、终止条件和单位，再决定尾值来源。[P02；E19]

9. 从叶状态恢复到完整策略回报

9.1 叶节点契约：先证明分段续算等价

固定两个根状态×16个首动作×技术seed44000—44003，128条参考轨迹。分别连续运行16步，与第8/12步保存完整状态和随机数状态后恢复对照，尾段只补剩余步数而非重新运行完整窗口。遇真终止不补造轨迹。[E20—E21]

G_(T) = G_(l) + 1_({not terminal at l})γ^(l)G_(T − l)^(tail).

进入叶节点的那一步奖励已在前段计算，不重复加；恢复时刻、路线进度、到达标志、外部对象状态及RNG都必须一致。128条参考轨迹、256分段对照和128原生rollout结果通过，1979条已记录转移，最大回报误差約2.84 × 10⁻¹⁴。128条中20硬安全终止、108到时间上限、0到双车终点；说明接口正确，不说明均匀随机续接是任务教师。

9.2 在相同叶状态上比较两种明确策略

从seed44000的全部32个第8步叶状态取样，不按回报挑选。每个叶状态×4新seed45000—45003×两种策略=256条续行：均匀随机可用动作，或原生Pure MCTS B64/H8每步重规划。均匀随机策略为：

π_(random)(a ∣ s) = 1/card (𝒜_(active)(s)).

有限窗口策略价值定义为：

$$V_m^\pi(s)=\mathbb E_\pi\left[\sum_{j=0}^{\min(m,\tau)-1}\gamma^jr_j\right].\tag{F31}$$

本轮先续行最多16步／8秒。MCTS搜索内部的安全事件不进入执行风险计数，只有最终选定动作经过状态转移后的事件进入统计。两种策略计算量差异巨大，该实验是策略效果对照，不是加速测试。[E22；P01]

9.4 原始根动作价值：去掉随机前缀，才知道评价的是什么

$$Q_T^\pi(s,a)=\mathbb E\left[r_0+\gamma V_{T-1}^\pi(s_1)\right],\qquad
Y_z(s,a)=\sum_{k=0}^{\min(T,\tau_z)-1}\gamma^kr_{z,k}.\tag{F32}$$

P07的rollout框架依据是“候选动作单步成本＋明确基础策略的后续成本”；本项目改为折扣奖励、固定联合动作和随机MCTS续行，不实现其逐智能体rollout，不继承策略改进保证，也不称为Q^(opt)。

10. 统计识别与任务目标：为何后来分成两条路径

10.1 “采到均值第一”不等于“已识别最佳动作”

Jamieson与Nowak讨论固定置信度最佳臂识别，在规定采样/分布假设下用候选动作与最强竞争动作的区间分离作为停止依据。当前4/8seed完整执行回报可作经验比较，但不自动满足这些保证。两个动作的配对差值及标准误只作描述：[P09；E25]

$$D_z(a,b)=Y_z(a)-Y_z(b),\quad
\overline D=\frac1n\sum_zD_z,\quad
s_D^2=\frac1{n-1}\sum_z(D_z-\overline D)^2,\quad
\mathrm{SE}_D=s_D/\sqrt n.\tag{F33}$$

同seed共用随机索引不证明相同轨迹；连续整数seed也不自行证明独立同分布。树内访问数不能替代外层执行样本数。新旧两批分别统计，合并12次只是补充，不把早期用于筛选的4次重复算成独立确认。

10.2 保守区间与有限样本：程序可正确，证据仍不足

依据冻结奖励范围、最多128步和0.99折扣，审计得到回报保守包络约[ℓ, u] = [−320.0195, 133.3926]。它来自源码而非观察最小最大值。对32个状态—动作条目，固定样本的Hoeffding＋并集界示例为：

$$c_n^{\mathrm H}=(u-\ell)\sqrt{\frac{\log(2M/\delta)}{2n}},\quad M=32.\tag{F34}$$

n = 8, δ = 0.05的事后示例半宽约303.20，不能排除任何动作。这不表示差异真的有303回报单位；表示这个保守方法缺乏辨别力。[E25]

Maurer与Pontil的Theorem 4提供方差敏感界。将原[0,1]单侧式按回报范围缩放、合并双侧后，项目实现：[P10；E26]

$$c_n^{\mathrm{EB}}=\sqrt{\frac{2s_n^2\log(4/\alpha)}{n}}+
\frac{7(u-\ell)\log(4/\alpha)}{3(n-1)},\quad n\ge2.\tag{F35}$$

$$L_a=\max(\ell,\overline Y_a-c_n),\qquad U_a=\min(u,\overline Y_a+c_n).\tag{F36}$$

样本方差小不允许删掉范围修正项。独立、有界、策略和分布固定等假设必须另行核验；读取一个certified=True字段并不创造统计证明。示例δ是统计覆盖错误预算，不是事故限额，也不能倒写为原实验预注册标准。

若将来按预先登记检查点反复查看，可分配：

$$\alpha_{a,k}=\frac{\delta}{32k(k+1)},\qquad
\sum_{a=1}^{32}\sum_{k=1}^{\infty}\alpha_{a,k}\le\delta.\tag{F37}$$

F37是项目用并集界构造的可求和错误预算，受时间一致置信序列研究启发；不是直接实现Howard等的更紧算法。不能追加新批次后把检查点编号清零直到结果好看。[P11]

10.3 回报最大化的近优条件与自比较修正

在所有区间同时覆盖真实均值时，保守的可排除条件为U_(a) < max_(b ≠ a)L_(b)。精度条件改为排除自身比较；本文用上标ub表示此前报告的“+”上界记号，数学含义不变：

R_(Q)^(ub)(a) = max (0, max_(b ≠ a)(U_(b) − L_(a))),   max_(b)μ_(b) − μ_(a) ≤ R_(Q)^(ub)(a).

R_(Q)^(ub)(a) ≤ ϵ_(Q)时才可作相应近优判断。早版把b = a也放入最大值，会把动作自身区间宽度当作劣势，导致ε=0时难以确认明显领先动作；本次离线契约已修正，不把旧表达保留为当前规则。[E26]

使用当前宽范围，即使假设零方差，示例采样数128/256/1024时范围项仍约93.71/48.07/12.54。这个计算不是所有算法的样本量下界，也不是建议立即运行4096—32768条轨迹。它说明不能用“再加8个seed”无止境追逐唯一第一。

10.4 复合奖励与任务完成时间不等价

奖励拆分报告核验384条轨迹、25691转移；纯奖励函数与保存值一致。一个实际样本均值反例来自step73新8seed：[E27]

  ----------------------------------------------------------------------------------
  首步动作     平均复合回报    A到达秒数    B到达秒数   双车全部完成    单车时间之和
  ---------- -------------- ------------ ------------ -------------- ---------------
  (1,3)             62.8936       34.250       20.125         34.250   54.375车辆·秒

  (3,1)             62.0769       32.000       24.125         32.000   56.125车辆·秒
  ----------------------------------------------------------------------------------

前者回报高0.8168，但两车全部完成慢2.25秒，同时B更早、单车时间之和更小。任务目标分别对应：

T_(all) = max (T_(A), T_(B)),   T_(sum) = T_(A) + T_(B).

每辆车首次到达的折扣目标奖励为：

G_(goal) = 15γ^(n_(A) − 1) + 15γ^(n_(B) − 1).

F40不能由F39的最大值唯一决定，再加效率/舒适性/安全项，不能把“允许损失1回报”换成“最多慢1秒”。这不是加总错误，而是目标不同。后续不得在未说明目标变更的情况下把秒制指标替换原训练目标。

10.5 秒制辅助目标与约束：接口完成，未成为部署目标

定义正常双车配置终点到达时间T_(ok)；发生硬安全失败时令其为+∞，同一步既到达又硬失败则硬失败优先。缺失日志直接技术HOLD。辅助成本为：

C₆₄ = min (T_(ok), 64s),   J_(T)(s, a) = 𝔼[C₆₄ ∣ s, a, π].

硬失败或64秒内未完成的时间成本取64秒，同时单独保留失败/截断标志，不能把“失败很早”当作“完成很快”。该成本不乘0.99折扣，原MCTS内部奖励与折扣保持不变。64秒是继承的开发评价窗口，不是用户已批准的业务时限。[E27—E28]

借鉴CPO把目标与约束分开，而非用时间收益抵消风险：[P12]

min_(a)J_(T)(s, a),  p_(H)(s, a) ≤ η_(H),   p_(F)(s, a) ≤ η_(F).

H为实际执行硬安全事件，F为窗口内未正常完成，包括硬失败和人工截止。当前没有执行CPO，也没有继承其策略更新保证。风险限额η_(H), η_(F)不等于统计错误预算δ。

成本越小越好的近优上界必须换向：

R_(T)^(ub)(a) = max (0, max_(b ≠ a)(U_(a) − L_(b))),   J_(T)(a) − min_(b)J_(T)(b) ≤ R_(T)^(ub)(a).

条件接受需要U_(H)(a) ≤ η_(H)、U_(F)(a) ≤ η_(F)及R_(T)^(ub)(a) ≤ ϵ_(t)，并且覆盖/采样规格真实有效。若用时间关系排除a，优势竞争动作b还必须已有可行性依据，不能因为它平均更快便用它删除可能更安全的动作。未知可行性不能先过滤来人为缩小竞争集合。[E28]

新8seed时间区间用范围[0,64]代入F35后全部仍为[0,64]。二项零事件的单侧上界例子为：

$$\sum_{j=0}^{x}{n\choose j}p_U^j(1-p_U)^{n-j}=\alpha,\qquad
x=0\Rightarrow p_U=1-\alpha^{1/n}.\tag{F44}$$

取n = 8, α = 0.05/96得到约0.6113，是宽上界而非事故概率估计61.13%；点观察仍0/8。该公式来自NIST的二项反演方法，不是新研究论文；也不提供全矿认证。[P13；E28]

实际接口输出HOLD_SPECIFICATION，每状态保留16/16动作、实际剪枝0。ε、风险限额、正式δ、检查点和新采样预算未批准，既不能任意填值，也不能把当前0.375/1.125秒的样本差反向选成通过门槛。

11. 回到原论文：真正标准与项目适配边界

11.1 为什么本节改变了当前Gate

前面的统计契约回答“何时可以带保证地排除动作”，但用户的整体研究还包括一般开发评价、训练质量和工程收益。回查论文后，没有找到适用于本项目的统一ε秒数。因此，从本交接起，开发评价不再被ε未定阻塞；统计保证分支独立HOLD。 这是对前置条件范围的纠正，不是事后降低原冻结实验标准。[E29]

以下区分四种来源：原论文公式、论文实验配置/观察、当前项目实际实现、拟采用的项目评价契约。论文阈值是否可移植，取决于风险定义、车辆几何、参考点、单位、预测/执行时刻和分母，而不是数字看起来相近。

11.2 Lin等2025：安全节点剪枝，不是Top13分数剪枝

对应用户原PDF 362388.pdf，题名为 Safety-Critical Multi-Agent MCTS for Mixed Traffic Coordination at Unsignalized Intersections，DOI 10.1109/TITS.2025.3598727。不是另一篇roundabout论文。正式元数据和上传原文对应；本次交接查阅了原文第4、7、10页公式/表格。[P14；E29]

原文第7页式(22)的节点安全条件是：

Safe (n) = [Q_(risk)^(V2V) ≤ Q_(th)^(V2V)] ∧ [Q_(risk)^(V2H) ≤ Q_(th)^(V2H)] ∧ [d_(V2R) ≥ d_(min)].

Table I给出Q_(th)^(V2V) = 0.8、Q_(th)^(V2H) = 0.6、d_(min) = 1.0米。0.8/0.6是复合风险分数阈值，不是80%/60%碰撞概率；1米需要其车辆polygon到道路边界的定义。当前MineSim K13按神经分数删动作，没有实现同一套V2V/V2H/V2R硬安全契约，不能写成该论文hard safe-node pruning的完成版。

原始V2V风险如何形成

论文第4页式(7)—(8)定义动态安全距离，记Δv_(ij)为相对速度、Δθ_(ij)为航向差：

$$d_{\mathrm{safe}}=\max\{d_{\mathrm{base}},\kappa_v\operatorname{abs}(\Delta v_{ij})\}\prod_{k=1}^{3}\alpha_k,
\qquad \alpha_3=1+I_{\Omega_{\mathrm{app}}}+I_{\Omega_{\mathrm{int}}}.\tag{F46}$$

$$\alpha_1=1+\beta_1\frac{\operatorname{abs}(\Delta v_{ij})}{v_{\mathrm{ref}}},\qquad
\alpha_2=1+\beta_2\frac{\operatorname{abs}(\Delta\theta_{ij})}{\pi}.\tag{F47}$$

原文β₁ = β₂ = 0.2、d_(base) = 1.5米、κ_(v) = 0.3；表中的固定d_(safe) = 2米还用于固定阈值消融，不能将其当成完整方法处处固定2米。相对速度项单位必须配套解释，不能只复制数值。

论文式(9)—(12)把即时风险与预测期累计风险组合：

$$r_{ij}=\exp\left(-\frac{d_{ij}^{\min}}{d_{\mathrm{safe}}}\right)
\left(1+\lambda_v\frac{\operatorname{norm}(\Delta v_{ij})}{v_{\max}}\right),\qquad
\rho(d,d_s)=\left[\max\left(0,1-\frac{d}{d_s}\right)\right]^2\tag{F48}$$

$$R_{T_p}=\frac1{T_p}\sum_{t=1}^{T_p}\frac{\rho(d_{ij}(t),d_{\mathrm{safe}}(t))}{1+t},\qquad
Q_{\mathrm{risk}}^{V2V}=w_1^{V2V}r_{ij}+w_2^{V2V}R_{T_p}.\tag{F49}$$

F49保留原论文的离散求和符号；表中prediction horizon写5.0，迁移时必须明确离散步数、秒数和采样步长，不能机械把5秒当5个MineSim任意时间步。Table I的V2V权重为0.6/0.4。V2H原式(18)—(19)还结合人工驾驶状态预测分布与碰撞指示积分：

C_(ih) = ∫_(ŝ_(h) ∈ 𝒮_(h)^(t))ψ(ŝ_(i), ŝ_(h))𝒩(f_(IDM)(s_(h), η_(h)), Σ_(h)(t, η_(h))) dŝ_(h),   Q_(risk)^(V2H) = w₁r + w₂R_(T_(p)) + w₃C_(ih).

ψ在原文以预测距离是否小于安全距离定义；η_(h)为驾驶风格、Σ_(h)为状态不确定性，V2H权重0.4/0.3/0.3。本项目当前两个C06受控车试验没有因此获得同等的人工驾驶概率模型或已认证V2H阈值。 不具备对应对象/字段时标记不适用或HOLD，而不是把V2H风险自动填0。

原文与现有实现的另外两处边界

原文第7页式(26)使用模型与随机rollout混合，式(28)采用带访问次数幂的更新；项目近期Frozen FleetMCTS仍是自身均值Q/随机rollout及root-order结构，不能认为“都叫MCTS”就已逐字复现。原文道路惩罚分段与safe-node判据在阈值等号的处理也需迁移前逐项明确；本次保留原定义差异，不擅自改成项目硬约束。

论文实验K=1000、深度8、折扣0.95、探索系数1.0，作者观察300—600迭代趋稳、末段价值标准差低于0.05。这是特定回报尺度下的搜索实验观察，不是网络600轮的出处，也不是统一loss<0.05验收线。混合交通到达率92.6%±3.3%、碰撞率1.7%±0.6%是结果，不是允许1.7%碰撞的安全标准。

11.3 PET与MMTTC：都以秒计，但不是同一个指标

Lin原文将PET低于1.5秒记为违例。对已绑定的同一冲突区域，且A先离开、B后进入的非重叠事件，可以用以下项目记号表达PET：

PET_(A → B) = t_(B, enter) − t_(A, exit).

F51要求真实占用同一区域的进出时刻；同时占用/几何碰撞必须另记，不用简单截断负值掩盖重叠。只知道两条中心线交点或到达参照点时间，不能自动当作基于车身占用的PET。区域几何、车辆footprint、采样时间分辨率和事件配对方式，均属下一Gate待绑定字段。

Bu等2026的原文 Risk-aware unsignalized intersection management in unstructured mixed-traffic environment: a real-time hierarchical safety evaluation method，Transportation Research Part C 192:105890，DOI 10.1016/j.trc.2026.105890，依据用户上传PDF核查；本轮未成功获得出版社全文网页，不声称外网全文再次核验。第19页7.2.3定义MMTTC为所有时间、所有车辆对中的最小预测TTC，并使用1.5秒危险临界值：[P15；E29]

MMTTC  = min_(t, i < j)TTC_(ij)(t).

F52是对原文文字定义的数学概括，不是新增TTC模型。TTC依赖预测运动假设、车身几何及预测视窗；不能把当前日志任意一个ttc字段改名MMTTC就视为复现。PET是实际先后占用的事后代理间隔，TTC是当前状态下的预测冲突时间，两者阈值恰好均为1.5秒，不表示物理含义相同，更不表示允许延误1.5秒。

Bu的TTT是连续1000辆混合交通车辆全部通过交叉口所需总时间。项目双车T_(all)可借鉴“完成效率”的思想，但不能直接冠以完全等价的1000车辆TTT。其traverse stage参数38秒也不是当前64秒评价窗口的出处。原文的分层安全评价、候选通行权和非结构化路口路径/速度规划，不等于当前route-constrained两车纵向搜索。

11.4 Neural A*：同时看规划质量和搜索效率

Yonetani等ICML 2021第4.3节使用Opt、Exp和Hmean。Opt为得到最短路径的比例；Exp为相对标准A*的节点扩展下降；调和平均兼顾两者。下式将原文Exp记为E_(red)，以免与指数函数混淆：[P16；E29]

$$E_{\mathrm{red}}=\max\left(100\frac{E_{\mathrm{Astar}}-E_{\mathrm{model}}}{E_{\mathrm{Astar}}},0\right),\qquad
\operatorname{Hmean}=\frac{2\operatorname{Opt}E_{\mathrm{red}}}{\operatorname{Opt}+E_{\mathrm{red}}}.\tag{F53}$$

原论文用验证集最高Hmean选权重，再在测试集报告bootstrap均值和95%置信界。项目可借鉴“质量与搜索开销联合评价”“分离验证选模与留出测试”，但当前没有已知最优矿卡联合规划真值，不能把“符合部分教师排序”命名为原文Opt。也不能把完成率和扩展率随意代入同一Hmean后，宣称复现Neural A*。

此外，论文Exp对负效率剪为0是其规定；MineSim必须另外保留带符号的实际展开和wall-time变化，避免把变慢隐藏。当前K13教训正说明：实际访问root改变、forward及控制器开销都可使节点减少与端到端耗时方向不同。

13. 重要失败、误判及必须保留的修正

13.1 地图与运行层：不能跨层修复

CollisionLookup几何问题。 现象是部分新地图runtime报边界/碰撞失败。排查分离了真实bitmap gap与lookup车辆几何错误，发现XG90G后轴参考点下前后悬语义反置及矩形角点异常。最终修正几何和离散命中复核，必要的地图patch按真实CarFootprint做additive-only版本。以后禁止为满足错误lookup不断涂宽mask；全局几何改动必须回归旧地图/车型。[E01；E03]

IDM路线终点虚拟前车。 A1已访问目标路线却停在goal前约4.84米；分析发现free-road endpoint被当作带4.5米后部长度的实体前车。改为零长度停止点后通过。A2在远离终点的路中停车是不同问题，不能延用endpoint解释；旧A2当时需要leading-object选择诊断，后来阶段已更新，不能再次当当前主线。[E01]

地图入口找不到。 root807准备时旧semantic入口缺失，后找到实际源文件并匹配冻结SHA。处理是只读重新绑定，不自动恢复symlink或替换地图。以后禁止把No such file写成“地图被删除”；真实生产可行驶真值仍独立HOLD。[E06；E09]

13.2 任务中断与日志：不把“仍在看日志”当作“仍在运行”

首次9-root验证中断。 worker在RouteGeometryCache/get_state_at_progress中出现KeyboardInterrupt，OOM计数为0；这支持发生中断而非所记录OOM杀死，但不能仅凭traceback断言用户一定按了Ctrl+C。后续发现min只是数值钳位，不能说是全路径线性搜索。retry1增加进度、心跳和错误保存，六条缓存共约1.35秒、worker约12.04秒完成，没有证据支持永久缓存性能故障。以后先看实际耗时，不凭栈位置想象复杂度。[E06]

864矩阵前40项完成后消失。 返回日志停在第41项SEARCH_CALL_STARTED，无SEARCH_RETURNED/result；40项有完整result/progress。不能把start_new_session当作SSH断开后绝对存活保证，也不能仅此确证停止信号的具体来源。处理是新retry namespace保存40项完整SHA、归档第41技术中断，从未完成部分继续，最终合并864项；不删除旧目录、原名重跑或挑掉科学负结果。[E06]

tail -f无自动结束。 采集器已写HOLD、ZIP_VERIFIED、BUNDLE和RC=2，监控仍等待新日志，使用户多等。后续必须按done/RC/ZIP验证退出监控；Ctrl+C只结束监控前台，不向screen会话主动发停止命令。启动请求accepted或screen Detached仅表示会话启动，不是实验PASS；实例仍必须保持运行。

13.3 36-root绑定链：技术错误与科学身份错误要分开

V2字典遍历解包错误。 for r,p in rs把root字典列表误当成二元组列表，触发too many values to unpack。技术失败，无新MCTS/训练；retry必须新namespace，不能删START重来。

retry1未建目标目录。 copy2前漏建bound_sources导致FileNotFoundError。不能只补mkdir就宣称全链闭合；后续还要审查collector、runner、route-helper角色，禁止仅因源码有类似函数名就替代历史来源。

旧retry2验收不严。 静态复核发现空目录、非法JSON跳过、不同路径同名源码可能误匹配等漏洞；应停止使用旧PASS自动授权重建，改为只读采集真实源码、输入、输出，逐SHA/角色绑定。以后语法检查不够，还要测空输入、缺字段、目录生命周期、同名异文件、异常/HOLD打包与已消费namespace保护。[E07]

两个step0并非只错元数据。 最初只想以同episode其余root作provenance锚点；进一步原日志核查证明Q与访问数也来自另一seed。修正为恢复正确原始搜索记录，不能只改seed字符串。原34条不变，两个新raw记录另建冻结结果。以后匹配条件不能只用12维特征SHA，还需episode、step、完整provenance与搜索记录。[E07—E08]

归档漏检。 12/15剩余三项不是源已丢失，而是采集器只扫py/json，漏查已知FREEZE/DELIVERY ZIP。按清单限定候选、整体SHA优先补齐，不能无边界扫整盘或按文件名强认匹配。[E08—E09]

13.4 方法与验收误判：不是每个负结果都应修成PASS

原离线排序通过，被过早解释为数据没问题。 数据覆盖、Q支持和优化收敛当时尚未核实。后续修正为“在指定教师下优于基线”，不把问题全部归给网络接入方法。

增加总预算，被误解为每个动作都复查。 root807出现单次访问极低Q跨预算不变，证明需看每动作visit/回报而不只看root总B。

100%确认排序，被误解为可选唯一动作/可剪Top13。 mask不完整，C11出现14个未支配候选，新C06还可能删掉全部候选。静态模型分数不是安全证据，必须分开质量与删除依据。

更长时域，被误解为更正确真值。 H12/H16排序都变化；只有同轨迹分段能隔离记录回报窗口，仍不能证明某个H最优。后续转为明确续接策略和真实终止，不批量覆盖旧H8标签。

均值第一，被误解为已最佳。 旧新批次领先动作变化，step76新均值第一只在3/8配对胜出；既不强选，也不宣布等价。统计上未决和经验比较可以同时存在。

ε未定，被过度扩展为全项目暂停。 最新论文核查明确其只是保证分支规格。当前恢复论文式安全/完成/效率开发评价，同时保持旧统计组件HOLD。不能通过取消HOLD伪造保证，也不能再将保证分支变成全部研究的先决条件。[E25—E29]

14.4 One-shot与失败分类

预注册、input SHA、namespace absent、授权、START必须在有科学执行前就明确。START写入后原namespace永久消费，不因PASS、technical FAIL或scientific negative改变。技术retry需确认执行到哪一步、是否已有科学信息、保留原证据，另建授权和namespace。不得“结果不好就换seed”，也不得用降低门槛抹掉scientific FAIL。

Runtime被中断时，SIGKILL可能不运行任何finally/trap；不能承诺一定自动保存完整包。必须利用已有START、SEARCH_CALL_STARTED/RETURNED、result、progress、RC和SHA做部分结果盘点。成功完成的cell原样保留，技术未完成项在授权新namespace处理；不把原完成cell重跑一次再冒充第一次。[S01，第6—7节；E06]
