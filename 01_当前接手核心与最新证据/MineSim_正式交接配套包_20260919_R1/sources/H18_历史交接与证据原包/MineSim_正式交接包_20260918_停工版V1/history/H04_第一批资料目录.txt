一：项目总流程和论文架构对应
论文中的 MineSim 是一个面向露天矿区自动驾驶矿车规划任务的闭环仿真系统。对你当前复现来说，最重要的是理解 Simulation Engine 内部的闭环：场景读取、障碍车预测/更新、自车规划、自车控制、自车运动学更新、其他 agent 更新、日志和可视化。
官方场景 JSON / HD Map    ↓Environment Manager / Scenario Builder    ↓Prediction / Observation：得到其他车辆当前状态和可能未来轨迹    ↓Planning Algorithm：生成 ego 自车未来 trajectory    ↓Motion Controller：把 trajectory 转成加速度、转向角速度等控制量    ↓Ego Update Model：用运动学模型更新 ego 下一帧状态    ↓Agent Update Policy：更新其他障碍车下一帧状态    ↓Simulation History / Log → 2D Visualizer / Metrics    ↓进入下一帧循环
当前你已经跑通的链路可以概括为：IDMPlanner 控制 ego 自车；其他动态障碍车主要通过 replay policy 按官方场景轨迹回放；官方 2D Visualizer 读取 simulation log 并生成视频。
关键概念速记
概念 | 解释
ego | 自车，也就是被算法控制的矿车。
agent | 场景中的其他车/障碍车，不是你控制的 ego。
route | 全局路线，大方向上经过哪些道路段。
trajectory | 具体轨迹，每个时间点的位置、速度、航向角等。
planner | 生成 ego 未来 trajectory 的算法。
tracker/controller | 跟踪 planner 的 trajectory，算出加速度和转向等控制量。
motion/update model | 用车辆运动学把控制量转换成下一帧 ego 状态。
policy | 状态更新策略，常用于决定其他 agent 怎么动。

FusionPlanner：多传感器融合的矿用卡车多任务运动规划器
FusionPlanner: A Multi-task Motion Planner for Mining Trucks via Multi-sensor Fusion
上传版本：arXiv v3 / 2023；22页。重点：LiDAR-GNSS 融合、任务不确定性、证据融合、MiningNav、PMS。
1. 一页读懂
论文试图解决一个直接而困难的问题：在没有清晰车道线、道路边界模糊、夜间视觉弱、GNSS 可能中断的露天矿山中，怎样让矿卡直接根据感知信息输出稳定、可信的驾驶控制。作者没有采用传统“感知-预测-规划-控制”逐层串联，而是构建了从 LiDAR 点云与 GNSS 定位到转向、油门和制动的端到端模型。
模型不仅预测当前控制，还预测未来若干距离点的控制。因为 LiDAR 大约只有 10 Hz，而矿卡控制频率可能超过 50 Hz，作者利用历史帧对同一未来位置给出的多次预测进行融合。普通平均能够平滑控制，进一步的“证据融合”则用模型估计的不确定性给高置信预测更大权重。
这篇论文实际上包含三个成果：FusionPlanner 算法、MiningNav 测试基准和 Parallel Mining Simulator（PMS）。对 MineSim 而言，最容易直接借鉴的不是完整 LiDAR 网络，而是 MiningNav 的扰动测试设计、控制不确定性、GNSS 失效注入和多帧融合机制。

2. 摘要精读翻译
近年智能车辆运动规划取得了显著进展，但露天矿山作为典型的非结构化环境，因为作业条件复杂、环境恶劣，受到的关注较少。论文提出了一套露天矿山无人运输范式。首先，作者利用多传感器融合提出面向矿用卡车的多任务运动规划算法 FusionPlanner，使系统同时适应横向和纵向控制任务。其次，构建 MiningNav 基准，通过三种验证方式评价训练后算法在矿山运输道路上的可信性与鲁棒性。最后，引入面向露天矿山的高保真 PMS 仿真器，使用户能够从单车控制和多车调度两个视角管理运输。实验表明，FusionPlanner 能显著减少碰撞和人工接管，但仍不能消除所有分布外事件。
3. 研究动机与背景翻译
露天矿山具有大尺度装备多、作业连续、人工成本高和安全风险高等特点，适合发展无人运输；但矿山道路与城市道路不同：护墙、土路和可行驶区域常由同质材料组成，缺少清晰边界，交通参与者类别较少，纹理和语义特征稀疏。夜间、雨雪、沙尘等环境又削弱了相机作用，因此作者强调 LiDAR、毫米波雷达等非视觉传感器。
作者比较了流水线框架与端到端框架。流水线框架可解释、便于定位错误，但一个子模块失败可能拖垮全系统，而且多个模块与手工规则会增加时延。端到端框架可直接学习从原始感知到控制的映射，实时性和表示能力更强，但容易出现协变量偏移、因果混淆和黑箱问题。论文选择严格的离线模仿学习，以避免在真实矿场进行高成本在线强化学习。

摘要
本报告说明蒙特卡洛树搜索（Monte Carlo Tree Search，MCTS）如何被接入 MineSim-Dynamic 仿真项目，并基于云端证据包评估其当前表现。当前实现不是独立于原工程重新搭建一套规划系统，而是继承 AbstractIDMPlanner，复用原有路线搜索、占用图构建、前导目标抽取、轨迹接口与下游控制链路，将纵向决策核心替换为几何感知的 MCTS。规划器每个周期从 EgoState 与 DetectionsTracks 构造根状态和障碍物快照，在四个离散纵向动作上执行 300 次、最大深度 8 的树搜索，并将选定动作转换为 16 个、间隔 0.5 s 的轨迹点，交给配置中的 two_stage_controller_ilqr_tracker_KBM 执行。
安全机制由两层构成：第一层是硬约束式几何碰撞判断，障碍物预测占用在 0.5 m 安全边界上膨胀后与自车沿路径的多边形做相交检查；第二层是连续净距奖励，物理多边形净距低于 3.0 m 时产生二次惩罚。障碍物运动根据角速度在 CV、CTRV 或二者并集之间切换，并在 0.1 s 时间粒度上预计算未来占用。搜索采用 UCT 选择、随机扩展、带紧急制动尾部可行性检查的 rollout、折扣回传，并通过固定动作顺序、固定随机种子 42 和确定性平局规则保证可复现。
实验覆盖 Dapai 与 Jiangtong 两个确定性场景。MCTS 在两个场景中均为零车辆碰撞帧和零道路边界碰撞帧；Dapai 中 IDM 出现 21 个连续碰撞帧，而 MCTS 的最小净距为 0.522 m；Jiangtong 中两者均安全，IDM 的最小净距略高。MCTS 两场加权平均速度比 IDM 高 13.329%，但规划频率仅为 1.371 Hz 和 3.178 Hz，低于 10 Hz 控制参考频率；IDM 则为 22.777 Hz 和 15.223 Hz。速度差分得到的舒适性代理显示，MCTS 的 jerk 明显大于 IDM。综合判断：当前 MCTS 在复杂交叉冲突安全、通行进度和专家数据生成方面具有明确价值，主要工程短板是计算频率，其次是离散动作导致的平滑性不足；现有证据不足以宣称全场景安全或总体优于 IDM。
核心结论　当前 MCTS 已完成“可执行接入—几何安全—确定性诊断—专家数据—双场景对照”的闭环；适合作为复杂场景安全专家和离线教师，但尚不适合直接作为 10 Hz 高频在线规划器。

2. 项目规划链路与接入目标
2.1 原有 IDM 基线
IDMPlanner 继承 AbstractIDMPlanner，其职责由两部分组成：首先搜索通向目标的路线，其次使用 IDM 纵向策略沿路线控制自车。compute_planner_trajectory 在每个周期读取当前 EgoState 与观测，构建局部 occupancy map 和去重后的目标对象，然后调用继承的 _get_planned_trajectory 生成可执行轨迹。该基线计算量较低，适合常规纵向跟车，但对横向交叉冲突的表达能力有限。
2.2 MCTS 接入目标
接入目标不是推翻 MineSim-Dynamic 的仿真与控制框架，而是在保持接口兼容的前提下，将“当前状态直接映射为纵向轨迹”的反应式决策替换为“比较未来多步动作序列”的搜索式决策。为降低工程风险，MCTSPlanner 仍继承 AbstractIDMPlanner，复用以下成熟能力：
全局路线搜索及 ego path 表示；
当前观测到 occupancy map 与 unique observations 的转换；
前导对象抽取和路径进度计算；
AbstractTrajectory / InterpolatedTrajectory 输出接口；
仿真器的 propagate 接口和 two-stage controller 下游控制。
设计原则　只替换纵向决策核心，尽量不改变项目已有的路线、观测、轨迹和控制边界，使 MCTS 能够作为原规划器的兼容替代实现。

1　研究背景与本轮实验问题
1.1 MineSim-Dynamic 与当前研究主线
本次工作建立在现有 MineSim-Dynamic 闭环仿真链上，重点放在 local planner，而不是重新搭建仿真器。五种方法最终都通过既有控制与车辆模型执行。MCTS 沿全局 route 做纵向多步动作搜索，本轮实验主要检验：在动态车辆交互下，显式搜索多个未来动作序列，能否带来更一致的安全任务完成结果。
当前版本还没有神经网络参与搜索，决策来自 MCTS 本身。后续如果引入网络，目标也不是改变本轮已经验证的任务定义，而是尽量用更少的搜索计算接近高预算 MCTS 的决策质量。
1.2 为什么把 MCTS 放进这组对比
选择 MCTS 不是因为预设它一定最好，而是因为五种方法的决策机制差异很明显：IDM 偏反应式纵向控制，Frenet 和 Maneuver 通过生成候选轨迹再筛选，Simple 几乎不做环境决策；MCTS 则在离散动作树里反复模拟未来结果。把这些方法放在同一闭环中比较，可以直接观察“前瞻搜索”是否会转化为实际的任务收益。
这轮实验重点看三个问题：第一，MCTS 在当前两个完整场景中的任务完成是否更一致；第二，搜索预算增加后，动作和执行轨迹是否真的变化；第三，这些变化是否值得额外的计算时间。
1.3 这轮实验主要回答的问题
在相同场景和闭环执行条件下，四个主 Planner 的任务完成和安全表现有什么差异？Simple 作为下限参考放在旁边观察。

2.1 MCTS

每个 0.1 s 仿真步都会重新规划。当前观测中的障碍物先按 90 m 范围筛选，再用 CV/CTRV 生成未来占用。树搜索通过 Selection、Expansion、Rollout 和 Backup 更新根分支的 visits 与 Q；搜索结束后按当前实现的根节点选择逻辑给出动作，并生成控制参考。Decision Log 已经表明，最终动作并不是每一步都简单等于最大 Q 或最大 visits，因此这里把 Q/visits 用来解释搜索过程，而不把它们简化成单一决策规则。
正式基线：Budget=300，max_depth=8，tree dt=0.5 s，c_uct=1.4，gamma=0.99，seed=42，use_viability_rollout=true。
几何安全：预测占用按 0.1 s 离散；障碍物安全外扩 0.5 m；CV/CTRV 由角速度阈值切换。
奖励由 progress、speed、safety、comfort 和 terminal 等部分组成。即时奖励只是当前动作的一步评价，MCTS 还会通过后续模拟把未来结果回传到根节点。
2.2 IDM
IDM 先沿 GlobalRoutePathPlanner 生成的参考路线确定自车纵向位置，再根据当前 leading object 的距离、相对速度、目标速度、headway 和最小间距计算加速度。其优点是计算快、规则明确；限制是缺少显式多步动作树与主动横向绕行能力。当前有效配置包括 target_velocity=10.5 m/s、accel_max=1.0 m/s²、decel_max=3.0 m/s²、headway=1.5 s、min_gap=1.0 m。

A. MineSimBitMapPngLoader
源码位置：
devkit/sim_engine/map_manager/minesim_map_data/└── minesim_bitmap_png_loader.py

pixel_x = int((x - x_range[0]) * scale)pixel_y = int((y - y_range[0]) * scale)

local_x_range 起点 = 1000 mscale = 10 pixels/m车辆 x = 1012 m

Loader 就知道车辆对应 PNG 第 120 列。

一分钟理解本项目的变化
最初问题是“网络离线训练看起来尚可，为什么接入MCTS及剪枝后收益差”。后续没有直接增加训练轮数，而是沿证据逐层追查：先发现重复状态和低支持Q标签，再发现根访问分配失衡；均衡访问降低了数值波动，但完整排序仍不稳定。独立种子确认提取出可学习的部分关系，然而新状态上的泛化仍可能失败。来源拆分又把局部异常定位到两个相近C06状态，进一步证实4秒搜索截断遗漏的后段回报足以翻转排序。[E06；E11—E19]
随后建立了完整叶状态恢复、随机数恢复和折扣回报拼接；用明确续接策略获得到配置路线终点的执行回报；再回到原始根状态，强制执行一个动作后由冻结MCTS接管。完整回报虽然不再缺失这批样本的尾段，但不同动作很接近，均值第一名依然随批次变化。因此又区分了“经验比较”“统计保证”和“任务评价目标”：复合奖励不等于两车完成时间，统计置信参数也不等于交通安全限额。[E20—E28]
最后回查论文，发现论文并未统一要求先给出“最多慢多少秒”。当前恢复为两条清楚的路径：开发评价继续对齐交通安全、完成率、通行时间和搜索开销；有保证的动作删除独立保留HOLD。 这不是降低安全标准，而是不再把某一新增理论分支的前提强加到所有开发研究上。[E29]
