1.  Prediction Algorithm（预测周围的障碍车接下来的行为）

在本次 IDMPlanner + replay policy 复现中，障碍车主要来自官方场景轨迹回放，并没有重点使用复杂的深度学习预测模型。

输入：

当前场景中的其他车辆状态

车辆位置、速度、航向角

历史轨迹或场景给定轨迹

输出：

周围车辆未来一段时间的 predicted trajectory

即每辆障碍车未来可能经过的一串位置

云端代码地址：devkit/sim_engine/observation_manager/agent_update_policy/

相关文件：

devkit/sim_engine/observation_manager/agent_update_policy/idm/idm_agent.py

2.  Planning Algorithm（ego 自车未来轨迹规划）

输入：

ego 当前状态

地图和道路拓扑

目标区域

周围障碍车状态

prediction 给出的障碍车未来轨迹

处理：

先找一条全局 route path

再根据当前交通状态生成局部 trajectory

判断前方是否有障碍车

决定加速、减速、跟车、避让或停车

输出：

ego trajectory 未来几秒的一串轨迹点

（route：大方向路线，比如应该经过哪些道路段

trajectory：每一帧具体位置、速度、航向角）

云端代码地址：devkit/sim_engine/planning/planner/

相关文件：devkit/sim_engine/planning/planner/local_planner/idm_planner.py

devkit/sim_engine/planning/planner/abstract_idm_planner.py

ml_planner.py

3\. Motion Controller(车辆怎么根据planner的轨迹行走)

输入：

planner 给出的目标 trajectory

ego 当前车辆状态

处理：

计算车辆应该怎么转向

计算车辆应该加速还是减速

让车辆尽量跟踪 planner 给出的轨迹

输出：

车辆控制量 / 动态状态，用于驱动 Ego Update Model 更新下一帧 ego 状态

云端代码地址：devkit/sim_engine/ego_simulation/

5\. Agent Update Policy（动态障碍车的状态更新）

云端代码地址：/root/autodl-tmp/MineSim-Dynamic/devkit/sim_engine/observation_manager/agent_update_policy/

配置文件地址：

devkit/script/config/sim_engine/observation_agent_update_policy/

官方policy：

replay_policy_agents_box_track（障碍车按官方轨迹回放。）

reactive_policy_agents_idm（其他 agent 根据 IDM 规则运动。）

reactive_policy_agents_idm_improved（普通 IDM agent update policy 的增强版。）

reactive_policy_agents_multimodal_trajectory_prediction（预测其他车辆未来可能的多种轨迹。）

ego_centric_ml_agents_observation（以 ego 自车为中心，观察周围 agent，并用 ML 模型预测其他车辆轨迹。）

项目流程：

1\. Scenario / Observation

从官方场景中读取当前 ego 状态、其他车辆状态、地图和目标区域。

2\. Agent Prediction / Observation Update

得到其他车辆当前状态和可能的未来轨迹。

当前 replay 场景里，障碍车很大程度来自官方给定轨迹。

3\. Planning Algorithm

Planner 根据地图、目标、ego 当前状态和障碍车信息，生成 ego 未来 trajectory。

4\. Motion Controller

控制器根据 planner 给出的 trajectory，计算 ego 应该如何转向、加速或减速。

5\. Ego Update Model

用运动学模型更新 ego 下一帧状态。

6\. Agent Update Policy

更新其他障碍车下一帧状态。

可以是 replay，也可以是 IDM/reactive/ML prediction。

7\. 下一帧继续循环。

本次复现采用的是 IDMPlanner + replay policy。IDMPlanner 负责生成 ego 自车的未来轨迹；replay_policy_agents_box_track 负责将官方场景文件中的动态障碍车轨迹进行回放。因此，视频中 ego 车是由规划算法控制的，而其他障碍车主要按照官方给定轨迹运动。
